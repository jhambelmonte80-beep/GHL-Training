# Beginner GHL Academy — Client Mission Workspace Edition

This is an interactive, browser-based training recreation inspired by the GoHighLevel interface. It is not the official HighLevel application and does not connect to a live GHL account.

## What changed in this edition

Client missions now open the matching editable workspace inside the GHL-style application shell. You no longer need to leave the GHL-style interface and switch to a separate generic sandbox to perform the core repair tasks.

### Client mission workflow
1. Open **GHL Client Practice Workspace**.
2. Choose **Client Missions** in the left navigation.
3. Select a client request from the mission library.
4. Choose **Open in GHL Interface**.
5. Perform the repair in the matching workspace page.
6. Save the change and run the relevant test.
7. Use **Check My Work** in the client request banner to receive scored feedback.

### Editable workspace areas
- Contacts: create, edit, search and delete sample contact records.
- Opportunities: create and edit opportunities, assign owners and move cards between stages.
- Pipelines: add, rename, reorder and remove stages.
- Forms: add, edit, remove and configure fields; submit test leads.
- Field Mapping: create custom fields, select destination object/field and validate mappings.
- Workflows: configure triggers, add/remove actions, publish/pause and run simulated test contacts.
- Calendars: edit timezone, availability, duration, buffer, confirmation and reminder settings.
- Integrations: configure sample Facebook lead connection, source field and webhook settings, then run simulated diagnostics.
- Tasks: create and assign sample follow-up tasks.
- Execution Logs: inspect simulated test activity.

## Data and limitations

- Practice data is stored locally in the browser using local storage.
- The mission grader checks the local practice configuration and records.
- No real contacts are created, no external integrations are connected, and no email/SMS messages are sent.
- Interface names and available controls are educational approximations based on public HighLevel documentation. The actual product may differ by account permissions, location, Labs features and product updates.
- Use fake sample data only. Never enter client passwords, API keys, payment data or other secrets.

## Publish with GitHub Pages

Upload `index.html` and this `README.md` to the root of your repository. In GitHub, open **Settings → Pages**, choose deployment from the `main` branch and `/ (root)`, then save.


## Main GHL-style client practice workspace
The Mock Dashboard is now the primary GHL-style workspace. Open Client Missions from its left navigation, choose a client request, and launch the corresponding editable workspace (Contacts, Forms, Field Mapping, Pipelines, Opportunities, Workflows, Calendars, Integrations, Tasks or Execution Logs). Mission grading checks the saved local practice state. This is an educational simulation and is not connected to a live HighLevel account.
